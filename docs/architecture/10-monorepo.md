# Monorepo setup

## Layout

```
vidashort/
├── apps/
│   ├── design/         # static HTML prototype (no build)
│   ├── api/            # FastAPI (Python 3.12, uv-managed)
│   └── mobile/         # Expo SDK 57 (npm/yarn)
├── packages/
│   └── shared/         # shared TS types + zod schemas
├── docs/               # the architecture / spec tree
├── .claude/            # Claude Code local config
├── .github/            # CI workflows
├── CLAUDE.md           # entry point for agents
├── README.md           # human readme
├── package.json        # workspace root (npm workspaces, not pnpm — see note)
├── pyproject.toml      # api-only (uv)
├── .gitignore
└── .nvmrc              # node 22.x
```

## Why npm workspaces, not pnpm or turbo

- **One tool.** The user installs Node, runs `npm install`, done. No pnpm, no bun, no yarn.
- **No turborepo.** Phase 1–3 has 2 apps and 1 package. Build orchestration is overkill.
- **If we hit perf walls** (we won't, not at this size), we add pnpm in Phase 5.

## Where each app's package.json lives

```json

  "name": "vidashort",
  "private": true,
  "version": "0.0.0",
  "workspaces": ["apps/mobile", "packages/*"],
  "scripts": {
    "mobile": "npm --workspace apps/mobile run start",
    "api:dev": "cd apps/api && uv run uvicorn app.main:app --reload",
```

## OneDrive exclusion (Windows)

`node_modules/`, `.expo/`, `.venv/`, `__pycache__/`, and `*.db` must be excluded from OneDrive sync or the laptop freezes every time it does its thing.

There is no CLI to set this; the user has to do it via the OneDrive UI. The `docs/runbooks/onedrive-exclude.md` runbook lists the exact folders to exclude. (No scriptable way to do this from our side without writing a Windows registry hack, which is out of scope.)

## Path conventions

- **All `import` paths in TS use workspace aliases:** `@vidashort/shared` (not `../../../packages/shared/src/...`).
- **All Python imports are absolute:** `from app.routers import auth`, never `from ..routers.auth`.
- **All paths in docs use forward slashes.** Windows is fine with them.
- **OneDrive-rooted absolute paths** are written as `C:\Users\kenik\OneDrive\Pictures\vidashort\...` only in the root CLAUDE.md and the runbook. Everywhere else, use repo-relative paths (`apps/mobile/...`).

## What you do NOT add to this monorepo

- ❌ A separate `frontend/` or `web/` directory. (If we ever need a web, it's `apps/web/`.)
- ❌ A `backend/` directory at the root. Everything server-side goes in `apps/api/`.
- ❌ A `scripts/` directory at the root. Helper scripts live in `apps/api/scripts/` or in `docs/runbooks/` (as shell snippets, not files).
- ❌ A `tests/` directory at the root. Tests live next to the code they test.
- ❌ A `docker-compose.yml` at the root. Phase 2 has one in `apps/api/` for local Postgres + Redis.
