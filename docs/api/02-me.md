# Me endpoints

Current user profile, wallet, ad cap, streak. All authed.

## Conventions

- "Me" is implicit; no `{userId}` in the path.
- `PATCH /v1/me` does a partial update; only fields present in the body are updated.
- `DELETE /v1/me` is a soft delete: the user can sign in again within 30 days to restore. After 30 days, hard delete (Phase 5 cron).

## Endpoints

### GET /v1/me

- **Auth:** required
- **Response 200:**
  ```json
  {
    "user": {
      "id": "uuid",
      "email": "user@example.com",
      "name": "Maya",
      "role": "viewer",
      "avatarUrl": "https://...",
      "genres": ["romance", "ceo", "revenge"],
      "language": "en",
      "ageConfirmed": true,
      "onboarded": true,
      "createdAt": "2026-07-22T11:00:00Z"
    },
    "wallet": {
      "coins": 120,
      "vip": { "active": false, "until": null }
    },
    "adCap": {
      "used": 4,
      "limit": 100,
      "remaining": 96,
      "resetsAt": "2026-07-23T00:00:00Z"
    },
    "streak": {
      "day": 5,
      "lastClaimedOn": "2026-07-21"
    }
  }
  ```
- **Notes:**
  - This is the one endpoint the app calls on launch (and on app-foreground). It's our "who am I, what's my state" snapshot.
  - Cache: client-side 60s, but always re-fetch on pull-to-refresh.

### PATCH /v1/me

- **Auth:** required
- **Request (any subset):**
  ```json
  {
    "name": "Maya O.",
    "avatarUrl": "https://...",
    "genres": ["romance", "ceo"],
    "language": "en"
  }
  ```
- **Response 200:** `{ "user": <User> }`
- **Errors:**
  - `400 invalid_genres` — genre not in the allowed set (see `MockData.genres`)
  - `400 invalid_language` — language not in the supported set (en, yo, ig, ha, fr)
- **Notes:** `email`, `role`, `coins` are NOT updatable here. `coins` only via coin routes. `role` only by an admin.

### POST /v1/me/age-confirm

- **Auth:** required
- **Request:** `{ "confirmed": true }`
- **Response 204:** no body
- **Notes:** Records that the user has confirmed they are 17+. The signup flow blocks new users behind this on the client, but the server stores the flag for audit.

### DELETE /v1/me

- **Auth:** required
- **Response 204:** no body
- **Side effects:**
  - User row: `deleted_at = now()`, `email = "deleted-{uuid}@deleted.vidashort"`, `name = "Deleted user"`, `avatar_url = null`.
  - All `user_identities` for this user: hard deleted (so they can't sign in with Apple/Google again on the same device without restore).
  - All `comments` for this user: anonymised (body replaced with "[deleted]").
  - All `favorites` for this user: hard deleted.
  - `watch_history` for this user: kept (anonymous analytics).
  - `coin_txn` for this user: kept (financial record).
  - Active `vip_entitlements` cancelled at Apple/Google via RevenueCat.
  - `payout_requests` for this user (if creator): marked `cancelled`, no payout.
  - All `refresh_tokens` for this user: invalidated.
  - Restore window: 30 days. Within 30 days, the user can re-sign-in to the same account; we detect the deleted_at and offer restore.
  - After 30 days: hard delete. Phase 5 cron.

## User shape

```ts
type User = {
  id: string;          // uuid
  email: string;
  name: string;
  role: "viewer" | "creator" | "admin";
  avatarUrl: string | null;
  genres: string[];    // selected on genre-picker
  language: string;    // ISO 639-1
  ageConfirmed: boolean;
  onboarded: boolean;
  createdAt: string;   // ISO 8601
};
```

The `user` is shared across `/v1/me`, the auth responses, and embedded in many other responses. Don't duplicate the definition; import the type.
