# Entitlement endpoints

The paywall decision + the actual pay. This is the **core of the product**.

## Paywall decision order (locked)

The server follows this order in `services/paywall.py → decide()`:

1. **Is the user VIP?** If `vip_entitlements.expires_at > now()` → `path: "vip"`, `costCoins: 0`, free.
2. **Is the episode free?** If `episodes.is_free OR episodes.number <= series.free_episodes` → `path: "vip"` semantically (free), `costCoins: 0`.
3. **Does the user have ≥ 25 coins?** → `path: "coins"`, `costCoins: 25`, no reward.
4. **Is the user under the daily ad cap (100)?** → `path: "ad"`, `costCoins: 0`, `rewardCoins: 20`.
5. **Else:** `path: "premium"`, `costCoins: 0`, "Go VIP to keep watching" label.

The client mirrors this logic for instant UX (`apps/mobile/src/lib/paywall/decide.ts`), but the server is the source of truth.

## Endpoints

### POST /v1/entitlement/check

- **Auth:** required
- **Request:** `{ "episodeId": "uuid" }`
- **Response 200 (entitled):**
  ```json
  { "allowed": true, "source": "vip" | "coins" | "free" }
  ```
- **Response 403 (paywall):**
  ```json
  {
    "error": "entitlement_required",
    "message": "Unlock this episode to keep watching",
    "details": {
      "paywall": {
        "path": "coins",
        "costCoins": 25,
        "rewardCoins": 0,
        "remainingAds": 96,
        "label": "Use 25 coins"
      }
    }
  }
  ```
- **Notes:** This is a **read-only** check. It does NOT deduct coins, does NOT count toward ad cap. The mobile client uses this to render the paywall modal *before* the user commits, but the actual pay is on `/unlock`.

### POST /v1/entitlement/unlock

- **Auth:** required
- **Request:** `{ "episodeId": "uuid", "source": "coins" | "ad" | "vip" }`
- **Response 200 (success):**
  ```json
  {
    "ok": true,
    "source": "coins",
    "coinsAfter": 95,
    "creatorCreditedCoins": 15,   // 60% of 25 = 15
    "playbackUrl": "https://..."  // convenience: skip a round-trip
  }
  ```
- **Response 403 (failure):**
  ```json
  { "error": "insufficient_coins", "message": "...", "details": { "paywall": <PaywallDecision> } }
  ```
- **Errors:**
  - `403 insufficient_coins` (when source = "coins" and balance < 25)
  - `403 ad_cap_reached` (when source = "ad" and used = 100)
  - `403 vip_required` (when source = "vip" and not VIP)
  - `404 episode_not_found`
  - `409 already_unlocked` (this user already has the entitlement; idempotent, returns the existing one)
  - `429 rate_limited` (unlock spam protection, 10/min)
- **Side effects on success:**
  - **`source: "coins"`:**
    - `users.coins -= 25` (with row lock).
    - `coin_txn` row: `delta: -25, reason: "unlock", ref_id: episodeId, balance_after: <new>`.
    - `creator_earnings` row: `gross_coins: 25, creator_coins: 15` (60% of 25).
    - `users.coins` of creator += 15 (creator's loyalty balance, not withdrawable until payout).
    - `watch_history` row updated: `unlocked_via_coins: true`.
    - User is now entitled; future `GET /v1/content/.../stream` returns 200.
  - **`source: "ad"`:**
    - `ad_impressions` row: `watched_s: <from ad SDK>, completed: true, rewarded_coins: 20`.
    - `coin_txn` row: `delta: +20, reason: "rewarded_ad"`.
    - `users.coins += 20`.
    - User is now entitled for this episode.
    - Redis `ad_cap:{user_id}:{date}` INCRed.
  - **`source: "vip"`:**
    - `watch_history` row updated: `unlocked_via_vip: true`.
    - No coin change.
    - User is entitled.

## Idempotency

- `POST /v1/entitlement/unlock` is naturally idempotent: if the user is already entitled to the episode, return `409 already_unlocked` (client should ignore and proceed to stream).
- The client should still send the request in case the server hasn't yet seen the unlock (race).

## Creator credit math (locked)

When a user spends 25 coins to unlock an episode of a creator-uploaded series:
- **60% to the creator's loyalty balance:** 15 coins (1.50 Naira).
- **40% to platform revenue:** 10 coins (1.00 Naira).
- Loyalty balance is **not withdrawable** until the creator has ≥ 50,000 coins (₦5,000).
- Loyalty balance is **only generated by unlocks of that creator's content**, not by purchases or ads.

Creator earnings are tracked in `creator_earnings` (immutable ledger) and aggregated into `users.loyalty_coins` for the creator.

## Watch history

Every successful `GET /v1/content/.../stream` writes a `watch_history` row. Every `POST /v1/entitlement/unlock` updates the same row with the unlock source. The player also PATCHes the row periodically (every 10s) to save `position_s` for resume.

`watch_history.completed` is set true when the player reports `currentTime >= durationS - 2`. This unlocks "next episode" recommendation and counts toward "watched 3 → interstitial" trigger.

## Why this is the core endpoint

The paywall is the **revenue engine**. If this endpoint is wrong, we're either giving content away (lost revenue) or blocking VIP users (lost trust). Every code path is tested end-to-end before any release.

The full paywall decision tree is in `docs/backend/00-tree.md § "services/paywall.py"`.
